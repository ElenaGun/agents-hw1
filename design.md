# Design: мини-трекер

## Context
Статическая страница без сборки и зависимостей. Логику данных нужно отделить от DOM: в варианте B её можно проверить в Node, в варианте A она остаётся отдельным блоком функций внутри `<script>`.

## Данные
- Состояние: `{ tasks: Task[], filter: "all" | "active", nextId: number }`.
- `Task = { id: number, title: string, hours: number, done: boolean }`.
- Стартовые данные: id 1 «Чтение» 2 true; id 2 «Практика» 4 false; id 3 «Повторение» 2 false; `nextId = 4`.
- id выдаётся счётчиком `nextId` (после загрузки из хранилища: max(id)+1). `crypto.randomUUID` не используется: на file:// он доступен не во всех браузерах.
- Фильтр хранится только в памяти и не сохраняется.

## Доменные функции (`domain.mjs` в B, тот же набор внутри скрипта в A)
Все функции чистые и возвращают новый массив или объект:
- `createInitialTasks()` → стартовые три задачи.
- `validateInput(rawTitle, rawHours)` → `{ ok: true, value: { title, hours } }` или `{ ok: false, errors: { title?, hours? } }`.
- `addTask(tasks, { title, hours }, id)` → новый массив с задачей `done=false`.
- `removeTask(tasks, id)`, `toggleTask(tasks, id)`.
- `visibleTasks(tasks, filter)`: только для отображения.
- `summary(tasks)` → `{ totalHours, doneHours, progress }`.

## Валидация
- Название: `rawTitle.trim()`; пустая строка даёт ошибку «Введите название».
- Часы, по порядку:
  1. `rawHours.trim() === ""` → «Укажите часы». Проверка идёт до преобразования в число, поэтому пустое значение не превращается в 0.
  2. Запятая заменяется на точку (в требованиях пример «0,5»), затем `Number(...)`. Результат не конечный → «Введите число».
  3. `< 0.5` или `> 24` → «От 0,5 до 24».
  4. `!Number.isInteger(hours * 2)` → «Шаг 0,5».
- Поле — `<input type="number" min="0.5" max="24" step="0.5" inputmode="decimal">`. Встроенную валидацию браузера отключает `novalidate` на форме, чтобы ошибки показывались единообразно рядом с полями. Нюанс: при некорректном вводе в `type="number"` браузер отдаёт `value === ""`. Такой ввод даст «Укажите часы» — это допустимо, задача всё равно не добавляется.
- Ошибка выводится в элементе под полем; поле получает `aria-invalid="true"` и `aria-describedby` на этот элемент. При ошибке форма не сбрасывается. При успехе форма очищается, ошибки снимаются.

## Расчёты
- `totalHours = Σ hours` по всем задачам.
- `doneHours = Σ hours` по задачам с done=true.
- `progress = totalHours === 0 ? 0 : Math.round(100 * doneHours / totalHours)`.
- Шаг 0,5 точно представим в двоичной арифметике, поэтому суммы считаются без ошибок округления.
- `Math.round` округляет .5 вверх (12,5 → 13); это принятое правило.
- Отображение часов: `toLocaleString("ru-RU")`, например «1,5 ч». Формат итогов: «Выполнено 6 из 8 ч · 75%».
- Проверка эталона: 2/8 → 25; 6/8 → 75; пустой список → 0.

## Интерфейс
- Порядок блоков: форма (Название, Часы, «Добавить»), фильтр («Все» / «Активные», радиокнопки с `<fieldset><legend>`), итоги, список.
- Строка списка: чекбокс done с `<label>` по названию задачи; кнопка удаления с доступным именем «Удалить: <название>».
- Перерисовка — функция `render(state)`: список строится из `visibleTasks`, итоги — из `summary(state.tasks)`.
- Узкий экран: `<meta name="viewport" content="width=device-width, initial-scale=1">`, `box-sizing: border-box`, ширины `max-width: 100%`, гибкая раскладка с переносом, длинные названия переносятся (`overflow-wrap: anywhere`), фиксированных ширин больше 390 px нет.

## Хранилище (необязательно)
- Ключ, например `mini-tracker.tasks.v1`; значение — JSON массива задач.
- Все обращения к localStorage обёрнуты в try/catch. При исключении в чтении или записи выставляется флаг `storageAvailable = false` и показывается сообщение «Хранилище недоступно: изменения не сохранятся после перезагрузки». Работа продолжается в памяти.
- Загруженные данные проверяются: массив, корректные поля, часы проходят ту же валидацию. Некорректные данные дают стартовый пример и сообщение.
- Ограничение file://: поведение localStorage для страниц file:// зависит от браузера. Хранилище может работать, быть общим для всех локальных файлов, быть отключено политикой или очищаться. Гарантии сохранения между перезапусками нет; сообщение о недоступности покрывает только случаи, когда браузер выбрасывает исключение.
- Приёмочные сценарии со стартовыми числами проверяются на чистом хранилище.

## Варианты поставки
- **A** (`tracker-v2.html`): открывается напрямую через file://, модули не используются.
- **B**: `index.html` подключает `styles.css` и `<script type="module" src="app.mjs">`; `app.mjs` импортирует `domain.mjs`. `domain.mjs` не обращается к DOM и localStorage.
- Ограничение B: в части браузеров (например, Chromium) ES-модули не загружаются со страниц file:// из-за политики CORS. Для B нужен любой локальный статический сервер (например, `python3 -m http.server`), который отдаёт `.mjs` с JavaScript MIME-типом. Это ограничение фиксируется в README или комментарии в `index.html`.
- Тесты B: `tests/acceptance.test.mjs` на встроенных `node:test` и `node:assert/strict`, запуск `node --test tests/`. Тестируется только `domain.mjs`.

## Risks / Trade-offs
- Замена запятой на точку работает только для ввода, который браузер передал как строку. Для `type="number"` это зависит от локали браузера.
- Тесты B не покрывают DOM; требования к интерфейсу, 390 px и подписям проверяются вручную.
- Для A доменная логика не тестируется автоматически без дополнительной обвязки; проверка — вручную или переносом тех же функций.
